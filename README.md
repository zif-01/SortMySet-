# SortMySet

**SortMySet** — инструмент для локальной сортировки экспортированных плейлистов Apple Music в последовательность с плавными переходами для DJ-сета.

Программа читает XML-библиотеку Apple Music, анализирует доступные аудиофайлы или метаданные, оценивает совместимость соседних треков и сохраняет новый XML-плейлист с обновлённым порядком.

## Возможности

- Чтение обычного XML-экспорта библиотеки Apple Music или iTunes.
- Извлечение треков и состава выбранного плейлиста.
- Анализ локального аудио:
  - BPM и ритмическая сетка;
  - тональность и Camelot-код;
  - RMS/ритмическая энергия;
  - mood-теги через опциональный `musicnn`.
- Учет метаданных как fallback при отсутствии аудиофайла.
- Опциональное скачивание недоступных треков через `yt-dlp` и нормализация через `ffmpeg`.
- Перестановка треков с учетом BPM, гармонии, энергии и жанрового настроения.
- Воспроизводимые результаты: одинаковые входные данные и указанный seed дают одинаковый порядок.
- При отсутствии seed создается случайный cryptographically secure seed и первый трек зависит от него.
- Масштабируемая вариативность: на небольших сетах изменения минимальны, на длинных сетах могут быть заметнее.
- Сохранение исходной структуры plist и метаданных треков.

## Как это работает

```text
Apple Music XML
       │
       ▼
Tracks + Playlist Items
       │
       ├──► Доступный Location ──► локальный аудиофайл
       │
       └──► Недоступный Location ──► опционально yt-dlp + ffmpeg
                                           │
                                           ▼
                                 Кэшированное аудио
                                           │
                                           ▼
                              Librosa / musicnn анализ
                                           │
                                           ▼
                     BPM + Camelot + Energy + Mood
                                           │
                                           ▼
                         Функция стоимости перехода
                                           │
                                           ▼
                    Жадный сортировщик + локальный поиск
                                           │
                                           ▼
                              Новый Apple Music XML
```

### Этапы pipeline

1. **Парсинг XML**
   - Загружается через стандартный модуль `plistlib`.
   - Извлекаются ID треков и элементы целевого плейлиста.
   - Исходные метаданные остаются в выходном plist.

2. **Поиск аудиофайлов**
   - Поле `Location` преобразуется из `file://` ссылки в локальный путь.
   - Потоковые треки и недоступные локальные файлы помечаются как requiring acquisition.
   - Если доступно `BPM`, `Key` или `Energy` в XML, они используются как fallback-признаки.

3. **Аудиоанализ**
   - `librosa` определяет темп и ритмические особенности.
   - Chroma-признаки сопоставляются с тональностью.
   - RMS/onset-признаки формируют оценку энергии.
   - Для ключей применяется Camelot-схема.

4. **Musicnn-анализ, необязательный**
   - Модель `MTT_musicnn` или `MSD_musicnn` формирует временной набор музыкальных тегов.
   - Средние вероятности тегов превращаются в normalized mood embedding.
   - Сходство embedding влияет на плавность перехода.

5. **Оптимизация порядка**
   - Соседние треки оцениваются по темпу, тональности, энергии, настроению и повторению исполнителя.
   - Сначала строится детерминированный жадный вариант.
   - Затем применяется локальный поиск перестановок.
   - Размер seed-вариативности растет вместе с размером плейлиста.

6. **Экспорт**
   - В исходном plist заменяется только массив `Playlist Items`.
   - Метаданные треков и остальные поля библиотеки сохраняются.
   - Создается валидный XML для повторного импорта в Apple Music.

## Установка

### Базовая установка

Требуется Python 3.10 или новее.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
```

Этой установки достаточно для чтения XML и работы с метаданными или готовыми признаками.

## Графический интерфейс

Базовый desktop GUI построен на стандартной библиотеке `tkinter`, поэтому для его запуска не нужен отдельный UI-фреймворк.

После установки проекта запустите:

```bash
sortmyset-gui
```

GUI позволяет:

- выбрать входной XML-файл;
- выбрать плейлист из найденных в файле;
- задать выходной XML и JSON-отчёт;
- использовать случайный seed или указать его вручную;
- включить опциональный загрузчик недоступных треков;
- выбрать модель `MTT_musicnn` или `MSD_musicnn`;
- запустить сортировку в фоновом потоке;
- получить уведомление об успехе или ошибке.

Для запуска исходниками в среде с tkinter:

```bash
PYTHONPATH=src python -m sortmyset.gui
```

### Установка аудиоанализа

Для анализа локальных файлов установите опциональную группу `audio`:

```bash
python -m pip install -e ".[audio]"
```

Она включает `numpy`, `librosa` и поддержку чтения аудиофайлов через `soundfile`.

### Установка musicnn

Поддержка `musicnn` доступна для Python 3.10–3.12:

```bash
python -m pip install -r requirements-musicnn.txt
```

Файл установки специально обходает устаревшие ограничения версии пакета `musicnn 0.1.0`:

- вместо старого TensorFlow 1.x используется TensorFlow 2;
- используются современные совместимые NumPy и librosa;
- модель загружается только при явном вызове через `--musicnn`;
- отсутствие библиотеки не прерывает обычный локальный анализ.

## Экспорт плейлиста из Apple Music

1. Откройте Apple Music.
2. Выберите нужный плейлист или библиотеку.
3. Выполните **Файл → Экспортировать → Экспортировать плейлист**.
4. Передайте полученный XML-файл программе.

Наличие локальных путей в поле `Location` не гарантирует доступ к аудиофайлу. Для недоступных треков доступны только метаданные или опциональное acquisition.

## Быстрый старт

```bash
sortmyset Library.xml \
  --playlist "DJ Set" \
  --seed 42 \
  --output Sorted.xml \
  --report Sorted.report.json
```

Аргументы:

| Аргумент | Назначение |
|---|---|
| `input` | Входной XML-экспорт Apple Music или iTunes |
| `--playlist NAME` | Имя плейлиста; если не указан, используется первый |
| `--seed NUMBER` | Seed для воспроизводимой вариативности; при отсутствии создается случайный seed |
| `--output FILE` | Путь выходного XML-файла |
| `--report FILE` | Необязательный JSON-отчёт |
| `--acquire-missing` | Разрешить поиск и скачивание недоступных треков |
| `--cache-dir DIR` | Каталог для скачанного аудио |
| `--musicnn MODEL` | Включить `MTT_musicnn` или `MSD_musicnn` |

---

## Примеры

### Локальный анализ

```bash
sortmyset Library.xml \
  --playlist "Techno Set" \
  --seed 100 \
  --output Techno.sorted.xml
```

### С поддержкой musicnn

```bash
sortmyset Library.xml \
  --playlist "Evening Set" \
  --seed 7 \
  --musicnn MTT_musicnn \
  --output Evening.sorted.xml \
  --report Evening.report.json
```

Поддерживаемые модели:

- `MTT_musicnn` — теги MagnaTagATune;
- `MSD_musicnn` — теги Million Song Dataset.

### Для треков без доступного Location

```bash
sortmyset Library.xml \
  --playlist "DJ Set" \
  --acquire-missing \
  --cache-dir ~/.cache/sortmyset \
  --seed 42 \
  --output Sorted.xml
```

Перед использованием этого режима установите внешние программы:

```bash
# Debian / Ubuntu
sudo apt install ffmpeg
python -m pip install yt-dlp
```

Скачивание включается только явным флагом `--acquire-missing`. Подробнее: [ACQUISITION.md](./ACQUISITION.md).

## Функция совместимости треков

Переход из трека A в трек B оценивается по нескольким soft-признакам:

| Признак | Влияние |
|---|---|
| BPM | Учитывается разница темпа с обработкой половинного и двойного темпа |
| Camelot key | Совпадающие и соседние тональности получают меньший штраф |
| Энергия | Сильные скачки энергии могут быть ограничены или сохранены для контролируемого arc-сета |
| Mood embedding | Musicnn-теги помогают объединять похожие по настроению треки |
| Повтор исполнителя | Подряд идущие треки одного исполнителя получают дополнительный штраф |
| Confidence | Неуверенные признаки практически не влияют на оценку |

Музыкальность не сводится к одной формуле. Параметры стоимости и ручная проверка порядка остаются важной частью DJ-подготовки.

### Переходы по Camelot wheel

Наименьший штраф получают:

- одинаковые Camelot-коды;
- переходы между major/minor с тем же номером;
- соседние номера на wheel;
- более дальние гармонические перемещения по мягкой функции штрафа.

Если тональность неизвестна или confidence низкий, гармонический штраф не считается точным и почти не доминирует над остальными признаками.

## Seed и вариативность

Один и тот же `--seed` обеспечивает одинаковый порядок при неизменных входных признаках. Первый трек и последующие перестановки управляются этим seed.

- До 15 треков вариативность минимальна и ограничена локальным перемещением трека.
- На больших плейлистах допустимый радиус перестановок растет пропорционально размеру.
- Вариативность не должна ухудшать существенные BPM/Camelot-переходы ради случайности.
- Без seed создается случайный seed для каждого запуска, который сохраняется в JSON-отчете.

Пример для одинакового воспроизводимого результата:

```bash
sortmyset Library.xml --seed 42 --output Sorted.xml
```

Повторный запуск с тем же seed, теми же файлами и теми же версиями моделей должен дать тот же список треков.

## JSON-отчёт

Пример использования:

```bash
sortmyset Library.xml --seed 42 \
  --musicnn MTT_musicnn \
  --report Sorted.report.json \
  --output Sorted.xml
```

Отчёт содержит:

- seed запуска;
- исходный порядок;
- новый порядок;
- среднюю разницу BPM;
- среднюю гармоническую стоимость;
- среднюю разницу энергии;
- выбранную musicnn-модель;
- количество треков, получивших embedding;
- статус каждого acquisition-попытки.

Пример структуры:

```json
{
  "seed": 42,
  "original_order": [101, 102, 103],
  "sorted_order": [102, 101, 103],
  "average_bpm_change": 0.018,
  "average_harmonic_cost": 0.31,
  "average_energy_change": 0.12,
  "musicnn_model": "MTT_musicnn",
  "musicnn_embedding_count": 3,
  "acquisition": []
}
```

## Ограничения

- Apple Music XML не содержит музыкальную аудиодорожку и не дает право извлекать подписочное или DRM-контент.
- Потоковые треки могут отсутствовать в локальной файловой системе.
- Несуществующий или недоступный `Location` не считается ошибкой всего pipeline.
- Устаревшие ссылки и файлы с другим именем требуют ручной проверки или `--acquire-missing`.
- Определение тональности может отличаться между моделями и движками.
- BPM может определяться в половинном или двойном темпе.
- Оптимальный DJ-переход зависит от микса, энергетического arc-сета и музыкального вкуса.
- Musicnn-теги являются ориентиром, а не гарантированным определением жанра.

Подробности приобретения аудио:

- [ACQUISITION.md](./ACQUISITION.md)
- [LICENSES.md](./LICENSES.md)

## Ограничения загрузки аудио

`yt-dlp` и `ffmpeg` являются только инструментами обработки:

- скачивание включается вручную;
- запрос строится по исполнителю и названию;
- размер и длительность ограничиваются;
- файлы сохраняются отдельно в кэш;
- исходная библиотека и XML не перезаписываются;
- DRM и подписочные потоки не расшифровываются;
- при недостаточной уверенности трек пропускается.

Пользователь отвечает за соблюдение авторских прав, условий сервисов и местного законодательства.

